# Prerequisites - what the preflight's lines mean, and who fixes each

`.lokf/scripts/knowledge-preflight.sh` prints one line per thing a skill depends on, in the words of the tools it checked. A curator is chosen for knowing the subject, not the repository, and a reader may know neither. This table is the translation: what each line means, what it stops, who normally puts it right, and what to send that person. **You** is the person at the keyboard; **the maintainer** is whoever set the repository up; **an administrator** has the forge's settings.

When a person cannot act on a `missing` or `warn` line, write them a short request note, addressed to the maintainer or administrator: the preflight line as printed, the row's request, and what the person can still do meanwhile. For `identity`, say that being signed in to GitHub in a browser is not this machine being signed in; that is the usual confusion.

| Line | It means | It stops | Who | What to send them |
| --- | --- | --- | --- | --- |
| `host` | The computer, its shell, and whether it can compute a digest or run Python. | Only the curator's sampling step, when there is no digest tool. | you | "On a Mac, `shasum -a 256` stands in for `sha256sum`." |
| `bundle` | Whether the knowledge folder exists and how many concepts it holds. | Missing: every skill but the sidecar. | the maintainer | "There is no `.lokf/knowledge` here. Please run the lokf-sidecar skill once, or tell me which folder holds the bundle." |
| `sync` | The folder lives in OneDrive, Dropbox, Drive or iCloud. | Nothing; links and conflict copies behave differently there. | you | Nothing. Delete a "conflicted copy" file after reading it; rule 7 names it. |
| `git` | Whether the folder is under git, the bundle committed, and line endings pinned. | No git: pull requests, signed-commit checks, the scheduled loop. | the maintainer | "Is this bundle meant to be under git? If so, please add `.lokf/.gitattributes` from the sidecar's templates." |
| `endings` | Some bundle files use Windows line endings or start with a byte order mark. | Nothing here; other tools may misread them. | you, or the maintainer | "Please save these files as UTF-8 without BOM, or add the sidecar's `.gitattributes`." |
| `forge` | Which hosting service holds the repository, and whether the gate workflow is present. | No gate: nothing checks a confirmation after it is recorded. | the maintainer | "Please lay down `knowledge-registrar.yaml` with lokf-sidecar Step 5, or port it per the sidecar's portability page." |
| `identity` | Whether this machine is signed in to the forge, so a confirmation can carry the person's account. | Confirm and Correct now; naming the asker in docent feedback. | you, with the maintainer | "Please sign this machine in to GitHub from the terminal as me: install the GitHub CLI and run `gh auth login` (GitLab: `glab auth login`). My browser login does not cover it." |
| `signing` | Whether commits made here are signed, and with which kind of key. | The gate rejects a curation pull request the same person opens. | you, with the maintainer | "Please set up commit signing for me on this machine (knowledge-trust-ladder `docs/signing-commits.md`) and register the key on my forge account as a signing key." |
| `curators` | Whether the repository keeps a public key per curator for the forge-free gate, and whether yours is among them. | Confirmations you sign fail that gate until your key is on file. | an administrator | "Please add my public signing key as `.lokf/curators/<my login>.asc` or `.pub` in its own pull request; `docs/signing-commits.md` says how to export it." |
| `toolkit` | Whether `uv` and the `lokf` toolkit are installed. | Validation, conversion and queries, and six of the conventions script's ten checks; reading and editing still work. | you, or the maintainer | "Please install `uv` (docs.astral.sh/uv) and run `just lokf-install` in `.lokf/`." |
| `just` | Whether the `just` command runner is present. | Nothing; `uvx --from rust-just just` does the same. | you | Nothing. |
| `skills` | Which of the four skills are installed, and whether two copies differ. | Nothing; a stale copy may answer from an older version. | the maintainer | "Two copies of `<skill>` differ. Please reinstall the LOKF skills from one release, or remove the stale copy." |
| `copies` | Whether the scripts and workflows the sidecar laid down still match their templates. | Nothing; a drifted copy may miss a later fix. | the maintainer | "`<file>` differs from the sidecar's template. Please run the lokf-sidecar repair, or confirm the edit is deliberate." |
| `session` | Whether a person is present or the run is automated. | Unattended: the curator's review session. | nobody | Nothing; an automated run is meant to stop there. |
| `network` | Whether PyPI is reachable and `curl` exists. | Version checks, skill installs, the signing-key identity route. | the maintainer | "This machine cannot reach pypi.org, or has no `curl`. Please allow it, or tell me the `lokf` version to pin." |

The preflight changes nothing and is safe to run again; `ok` lines need no action; a `missing` line is a fact about this machine, not about the person. The repository contract checks that every line the preflight can print as missing or a warning has a row here.

# Prerequisites: what the website preflight's lines mean, and who fixes each

`scripts/website-preflight.sh` prints one line per thing the site depends on, in the words of the tools it checked, and runs the sidecar's own preflight inside it. This table is the translation: what each line means, what it stops, who normally puts it right, and what to send that person. **You** is the person at the keyboard; **the maintainer** is whoever set the repository up; **an administrator** has the forge's settings.

When a person cannot act on a `missing` or `warn` line, write them a short request note, addressed to the maintainer or administrator: the preflight line as printed, the row's request, and what the person can still do meanwhile.

| Line | It means | It stops | Who | What to send them |
| --- | --- | --- | --- | --- |
| `host` | The computer, its shell, and whether it can run Python, which fills the placeholders. | Nothing; `uv run python` stands in. | you | Nothing. |
| `bundle` | Whether `.lokf/knowledge/index.md` exists and how many concepts sit beside it. | Missing: every step. | the maintainer | "There is no knowledge bundle here. Please run the ktl-sidecar skill once, then ktl-librarian." |
| `sidecar` | What the sidecar's own preflight says about this host. | Nothing. The site builds from what the sidecar's scripts report, so a warning there reaches the pages. | the maintainer | The sidecar's own prerequisites page has the row for the line it printed. |
| `report` | Whether `.lokf/scripts/knowledge-report.sh` is there and prints a health line; the concept pages show the labels it prints. | Missing: the build and the workflow. | the maintainer | "The sidecar predates `knowledge-report.sh` (ktl-sidecar 0.30.0). Please run the ktl-sidecar repair so `.lokf/scripts/` carries it." |
| `toolkit` | Whether `uv` is installed and `.lokf/uv.lock` exists and is committed. The build runs Hugo, Pagefind and `lokf export` through uv, each from a lock file. | Missing: the build; a lock not in git: the workflow. | you, or the maintainer | "Please install `uv` (docs.astral.sh/uv)." For the lock: "Please run `uv lock` in `.lokf/` and commit `uv.lock`." |
| `git` | Whether the folder is under git, on which forge, and its default branch. The site's address and its repository follow from the origin remote. A gitignored `.lokf/` cannot be built in CI. | No GitHub remote, or a gitignored bundle: the workflow. | the maintainer | "Please tell me the repository's owner and name on GitHub, and its default branch." For a gitignored bundle: "The site can only be built locally; shall I skip the workflow?" |
| `pages` | Whether another workflow or tool already publishes this repository's GitHub Pages, or a custom domain is set. | The deploy: two publishers overwrite each other's site. | an administrator | "This repository already publishes Pages from `<file>`. The knowledge site is built but not deployed until that publisher is retired or the two are merged; `references/deploy.md` has the options." |
| `address` | The site's address, for Step 1's `<SITE_URL>` and `site.toml`'s `baseURL`: the Pages API's `html_url` once Pages is on, and before that `https://<owner>.github.io/<name>/`. A warning means `baseURL` differs from where Pages serves the site. | A warning: the site's links, search and social cards, which point at the wrong address. | the maintainer | "Pages serves the knowledge site at `<html_url>`, but `website/site.toml` says `<baseURL>`. Please set `baseURL` to the first, or tell me which is right." |
| `mkdocs` | Whether `mkdocs.yml` is at the root: an mkdocs site, which the knowledge site replaces. | Nothing; Step 0 reads it once, and Step 5b retires it. | the maintainer | The retirement list in `references/deploy.md`. |
| `website` | Which folder the site is in or goes in: `website/`, or `ktl-website/` where `website/` is another site's. For an installed site, whether its files match the templates, whether `site.toml` still holds a placeholder, and whether it is the earlier Astro site. | Both folders another's: Step 1 and every step after it. A placeholder: the build. Drift: nothing, though a drifted copy may miss a later fix. | the maintainer | "`website/` holds another site, so the knowledge site goes in `ktl-website/`." For drift: "`<file>` differs from the template. Please run the ktl-website repair, or confirm the edit is intended." For the Astro site: "The site moves from Astro to Hugo. May I replace the files in `website/`?" |
| `workflow` | Whether `.github/workflows/knowledge-website.yaml` is installed. | Nothing; Step 5 installs it. | the maintainer | Nothing. |
| `readme` | Whether `README.md` exists and opens with a `#` title, the home page's source. | Nothing; with no README the home page opens with the bundle's own introduction. | you | Nothing, or add a `#` title to the README. |
| `docs` | Whether a `docs/` folder exists, how many Markdown pages git sees in it, whether `architecture.md` is one, and how many retellings it holds. | Nothing; the Guide part lists the home page alone, and the Architecture button is greyed. | nobody | Nothing. |
| `changelog` | Whether `CHANGELOG.md` exists and holds a released version in Keep a Changelog form. | Nothing; no release pages. | the maintainer | "The changelog has no `## [version] - date` heading, so it cannot become release pages. Keep a Changelog form would do it." |
| `assets` | Whether a `.assets/` folder of figures exists, and which files in it look like a logo. | Nothing; the site shows the Knowledge Trust Ladder logo. | you | Nothing, or name the logo file as `params.logo` in `site.toml`. |
| `schema` | Whether the repository has a LinkML schema at `src/<name>/schema/<name>.yaml`, at the root or under `.linkml/`, and else a domain vocabulary at `.lokf/schema/domain.yaml`. | Nothing; the Schema part shows the domain vocabulary or LOKF core, and the home page does not lead with it. A schema elsewhere is named in `site.toml`'s `schema`. | nobody | Nothing. |
| `workspace` | Whether the repository has `.github/workflows/knowledge-federation.yaml`, which makes it a domain host. | Nothing; the graph page greys the workspace. | nobody | Nothing. |
| `lint` | Which Markdown lint configurations the repository has, for Step 2 to exclude the generated folders from. | Nothing; a lint run over the generated folders fails until they are excluded. | the maintainer | "Please exclude `website/(dist\|generated\|resources\|\.venv)/` from the Markdown lint and link checks." |
| `session` | Whether a person is present or the run is automated. | Unattended: the placeholders need a person's values, so the skill stops after the screen. | nobody | Nothing. |

The preflight changes nothing and is safe to run again. An `ok` line does not need action. The skills repository's contract checks that every line it can print as missing or a warning has a row here.

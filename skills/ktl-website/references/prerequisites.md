# Prerequisites: what the website preflight's lines mean, and who fixes each

`scripts/website-preflight.sh` prints one line per thing the site depends on, in the words of the tools it checked, and runs the sidecar's own preflight inside it. This table is the translation: what each line means, what it stops, who normally puts it right, and what to send that person. **You** is the person at the keyboard; **the maintainer** is whoever set the repository up; **an administrator** has the forge's settings.

When a person cannot act on a `missing` or `warn` line, write them a short request note, addressed to the maintainer or administrator: the preflight line as printed, the row's request, and what the person can still do meanwhile.

| Line | It means | It stops | Who | What to send them |
| --- | --- | --- | --- | --- |
| `host` | The computer, its shell, and whether it can run Python, which fills the placeholders. | Nothing; `uv run python` stands in. | you | Nothing. |
| `bundle` | Whether `.lokf/knowledge/index.md` exists and how many concepts sit beside it. | Missing: every step. | the maintainer | "There is no knowledge bundle here. Please run the ktl-sidecar skill once, then ktl-librarian." |
| `sidecar` | What the sidecar's own preflight says about this host. | Nothing outright; the site builds from what the sidecar's scripts report, so a warning there reaches the pages. | the maintainer | The sidecar's own prerequisites page has the row for the line it printed. |
| `report` | Whether `.lokf/scripts/knowledge-report.sh` is there and prints a health line; the concept pages show the labels it prints. | Missing: the build and the workflow. | the maintainer | "The sidecar predates `knowledge-report.sh` (ktl-sidecar 0.30.0). Please run the ktl-sidecar repair so `.lokf/scripts/` carries it." |
| `toolkit` | Whether `uv` is installed and `.lokf/uv.lock` exists and is committed. The sync runs `lokf export` with `uv run --frozen`, and the workflow installs the toolkit with `uv sync --locked`. | Missing: the build; a lock not in git: the workflow. | you, or the maintainer | "Please install `uv` (docs.astral.sh/uv)." For the lock: "Please run `uv lock` in `.lokf/` and commit `uv.lock`." |
| `node` | Whether Node.js 22.12 or later is on the path. | Missing: the local build in Step 4; the workflow brings its own. | you | "Please install Node.js 22.12 or later (nodejs.org, or nvm) on this machine." |
| `npm` | Whether `npm` is on the path. | Missing: the local build. | you | "Please install Node.js; npm comes with it." |
| `git` | Whether the folder is under git, on which forge, and its default branch. `REPO`, `SITE` and `BASE` follow from the origin remote. A gitignored `.lokf/` cannot be built in CI. | No GitHub remote, or a gitignored bundle: the workflow. | the maintainer | "Please tell me the repository's owner and name on GitHub, and its default branch." For a gitignored bundle: "The site can only be built locally; shall I skip the workflow?" |
| `pages` | Whether another workflow or tool already publishes this repository's GitHub Pages, or a custom domain is set. | The deploy: two publishers overwrite each other's site. | an administrator | "This repository already publishes Pages from `<file>`. The knowledge site is built but not deployed until that publisher is retired or the two are merged; `references/deploy.md` has the options." |
| `website` | Whether `website/` exists: not yet, this skill's (and whether its files match the templates), or another site's. | Another site's: Step 1 and every step after it. Drift: nothing outright; a drifted copy may miss a later fix. | the maintainer | "`website/` already holds another site. Please say whether the knowledge site should replace it." For drift: "`<file>` differs from the template. Please run the ktl-website repair, or confirm the edit is intended." |
| `workflow` | Whether `.github/workflows/knowledge-website.yaml` is installed. | Nothing; Step 5 lays it down. | the maintainer | Nothing. |
| `readme` | Whether `README.md` exists and opens with a `#` title, the home page's source. | Nothing; the home page opens with the bundle's own introduction instead. | you | Nothing, or add a `#` title to the README. |
| `docs` | Whether a `docs/` folder exists and how many Markdown pages git sees in it. | Nothing; the Guide topic lists the home page alone. | nobody | Nothing. |
| `changelog` | Whether `CHANGELOG.md` exists and holds a released version in Keep a Changelog form. | Nothing; no Releases topic. | the maintainer | "The changelog has no `## [version] - date` heading, so it cannot become release pages. Keep a Changelog form would do it." |
| `assets` | Whether a `.assets/` folder of figures exists, and which files in it look like a logo. | Nothing; the site shows the Knowledge Trust Ladder logo. | you | Nothing, or name the logo file in `LOGO`. |
| `schema` | Whether a `justfile` in the root, a linkmo project or `.linkml/` has a `gen-doc` recipe, whose pages become the Schema topic. | Nothing; no Schema topic. | nobody | Nothing. |
| `data` | Whether a `build-browse` recipe writes SQLite databases the site could serve. The data page is off until `BROWSE` names their folder. | Nothing; no data page. | the maintainer | "The site can serve the data as SQLite databases for readers to browse in Datasette Lite. Shall it? They would be public." |
| `just` | Whether `just` is installed, when the sync builds the schema's pages or the data through a `just` recipe. | Missing: Step 4's local build of those pages; the workflow installs its own. | you | "Please install `just` (`uv tool install rust-just`), or say to leave the schema's pages off (`SCHEMA = null`)." |
| `lint` | Which Markdown lint configurations the repository has, for Step 2 to exclude the generated folders from. | Nothing; a lint run over the generated folders fails until they are excluded. | the maintainer | "Please exclude `website/(dist\|public\|src/content\|src/generated\|node_modules)/` from the Markdown lint and link checks." |
| `session` | Whether a person is present or the run is automated. | Unattended: the placeholders and the options need a person's values, so the skill stops after the screen. | nobody | Nothing. |

The preflight changes nothing and is safe to run again; `ok` lines need no action. The skills repository's contract checks that every line it can print as missing or a warning has a row here.

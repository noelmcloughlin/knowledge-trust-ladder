# Playbooks

* [ktl-sidecar skill](ktl-sidecar-skill.md) - Procedure that creates a .lokf/ sidecar from bundled templates, or repairs a missing or broken sidecar file: the tooling, docs, a dummy skeleton and the knowledge_bundle doorway link, then optionally the CI workflows (scheduled librarian, registrar gate, release, sync, ingest, federation) with the variables, secrets, Environments and tokens each needs, such as AGENT_API_KEY and KNOWLEDGE_SYNC_TOKEN. It then hands off to ktl-librarian.
* [Open the knowledge bundle in Obsidian](open-bundle-in-obsidian.md) - How a knowledge bundle meets an Obsidian vault: two vaults, the workshop someone keeps and the bundle opened as its own through the `knowledge_bundle` doorway, what Obsidian does with the link on each host, and why the bundle is never a real folder inside a vault.
* [The docent in Microsoft 365 Copilot](docent-in-m365-copilot.md) - How a person gets ktl-docent-m365, the docent packed with a snapshot of the bundle as a Microsoft 365 Copilot custom skill, from a release or by building it, adds it to a declarative agent, checks the first answer and keeps it current, what to do when a step fails, and why only the read-only roles go there.
* [ktl-librarian skill](ktl-librarian-skill.md) - Recurring procedure that scrapes the host repository, derives and maintains the .lokf/ concepts and their typed relations, audits the bundle, and hands off for human review.
* [ktl-curator skill](ktl-curator-skill.md) - A human curator's assistant: a one-screen report of what needs a person's attention, then a review session that records that person's confirm, correct, retire or send-back verdicts in the bundle's frontmatter, including on a domain host's member concepts.
* [ktl-docent skill](ktl-docent-skill.md) - The reader's side: it answers questions from the bundle first, with each concept's trust label, falls back to the repository when the bundle cannot answer, and records misses and disagreements for the librarian; it also answers for younger readers and from a domain host's workspace.
* [Knowledge sources](knowledge-sources.md) - Map of the repository locations this bundle was derived from, and how to re-check each on a future refresh.
* [Contributing](contributing.md) - How to work on the skills: no build step but the website's, the local checks to run before opening a pull request, the role boundary a change must respect, and which pages now hold the release and signing detail.
* [Releasing](releasing.md) - How a release happens: `semantic-release.yml` computes the version from Conventional Commits and promotes `CHANGELOG.md` on merge to `main` but never tags, and a maintainer's `publish.yml` run checks that version against the changelog, lets `gh skill publish` create the tag and release, dispatches `knowledge-release.yaml` to attach the bundle's zip, its domain vocabulary, its evidence table and, once `KNOWLEDGE_M365_ENABLED` is `true`, the Copilot zips, and asks the sibling hosts to sync.
* [Repository validation](repository-validation.md) - What CI checks on every pull request and weekly: the repository contract, the Agent Skills spec, shell and workflow linting, the install and website smoke tests, and Markdown, link and spelling checks.
* [ktl-prose skill](ktl-prose-skill.md) - The librarian's copy editor. It rewords the body of a concept an agent wrote, in plain English, before a person confirms it, changing the wording and never a fact or a frontmatter byte, and its script proves that only the wording changed.
* [Build, preview and edit the website](website.md) - How the project website in `website/` is built with Hugo from the README, a root `SPEC.md`, `docs/`, retellings, the knowledge bundle, `CHANGELOG.md`, the figures and, when the repository has one, a LinkML schema, each found with no setting; how to preview it locally with uv and `scripts/build.sh`; which file to edit for each kind of change; how raw HTML is cleaned; and how `knowledge-website.yaml` publishes it to GitHub Pages, on a push, weekly or by hand.
* [ktl-website skill](ktl-website-skill.md) - Procedure that installs a Hugo website for the knowledge bundle in `website/`, or in `ktl-website/` where `website/` is another site's, from bundled templates. The site finds the README, a root `SPEC.md`, the docs, retellings, the changelog, the figures, a LinkML schema and a domain host's workspace with no setting, shows a page per concept with its trust label, a health page and the knowledge graph, and builds with uv and no Node.js. A workflow publishes it to GitHub Pages once `KNOWLEDGE_WEBSITE_ENABLED` is set; the skill also repairs or updates a site it installed, moves its earlier Astro site to Hugo, and hands the maintainer the steps that retire an mkdocs site it replaces.
* [Curating a domain bundle](domain-bundle.md) - How the curator of a domain host confirms that a bundle belongs, what the domain's four concept types hold, what moves a member, and how to read the workspace the domain's releases build.
* [Knowledge outside the repository](knowledge-outside-the-repository.md) - How the ingest mirrors Confluence pages, web pages and PDFs, files in another git repository and a command's output into `.lokf/mirror/`, with the manifest `.lokf/ingest.yaml`, the lock, sensitivity, the weekly pull request, and how the librarian cites a mirror file.
* [The ktl command](ktl-command.md) - How the ktl package from PyPI installs the six skills for an agent (ktl skills install, status, path) and sets the GitHub variables, secrets, Environments and rulesets their workflows need (ktl gh plan, apply, secrets, enable, prune, check), from each skill's repository-settings.json catalogue.
